### 4.2 改 `match` 为 `map_or` 时的常见陷阱

| 模式 | 正确写法 | 注意 |
|---|---|---|
| `match X { Some(y) => f(y), None => default }` | `X.map_or(default, f)` | 当 `f` 是方法引用时, 用 `Type::f` 不用 `\|y\| y.f()` (redundant_closure lint) |
| `match X { Some(y) => f(y), None => g() }` | `X.map_or(g(), f)` | `g()` 需要立即求值, 注意副作用 |
| `match X { Some(y) => { stmts; result }, None => default }` | `X.map_or(default, \|y\| { stmts; result })` | 闭包块 |
| `match X { Some(y) => nested_match, _ => default }` | `X.map_or(default, \|y\| nested_match)` | 嵌套 match |
| `if let Some(ref y) = x[idx] { y.foo } else { default }` | `x[idx].as_ref().map_or(default, \|y\| y.foo)` | `ref y` 必须 `as_ref()` |

### 4.3 改完后必须检查后续 lint 触发

**改 `match Some/None` 为 `map_or(|x| x.method())` 会触发** `redundant_closure_for_method_calls` pedantic lint。
**正确写法**: `map_or(default, Type::method)`（方法引用，不用闭包）。
**历史 bug**: cpu/mod.rs 上批 3 处 `|info| info.X()` 触发 pedantic error, 已修复为 `CpuInfo::is_intel`。
