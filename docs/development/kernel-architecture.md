# AntX 内核架构设计

## 一、架构概述

AntX 内核采用**宏内核（Monolithic Kernel）**架构，聚焦**极简可用**目标。

### 极简设计原则

```
┌─────────────────────────────────────────────────────────────┐
│                        用户态                                 │
│  ┌─────────┐  ┌─────────┐  ┌─────────┐                    │
│  │  antxsh │  │ 用户程序 │  │  库     │                    │
│  └─────────┘  └─────────┘  └─────────┘                    │
└─────────────────────────────────────────────────────────────┘
                              │
                        系统调用接口
                              │
┌─────────────────────────────────────────────────────────────┐
│                        内核态                                 │
│  ┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────┐        │
│  │ 进程调度  │  │ 内存管理  │  │ HvFS    │  │ 基础驱动  │        │
│  └─────────┘  └─────────┘  └─────────┘  └─────────┘        │
│  ┌─────────┐  ┌─────────┐                                 │
│  │ PWID    │  │ 中断处理  │                                 │
│  └─────────┘  └─────────┘                                 │
└─────────────────────────────────────────────────────────────┘
```

**设计目标**：
- 极简：只保留最小必要功能
- 可用：尽快实现可运行、可交互
- 高效：用最少的代码实现核心能力

## 二、核心模块设计（极简版）

> 初期只实现最核心的功能，其他功能后续按需添加。

### 2.1 进程调度模块

**极简实现**：
- 仅支持进程创建、退出、调度
- 使用简单优先级队列
- 不支持线程（后续添加）

**关键数据结构**：
```c
struct process {
    uint64_t pid;
    uint64_t pwid;
    uint64_t parent_pid;
    uint64_t priority;
    void *stack;
    struct process *next;
};
```

### 2.2 内存管理模块

**极简实现**：
- 固定 4KB 页大小
- 简单页表映射
- 内存池分配器（避免频繁 malloc）

### 2.3 PWID 权限模块

**极简实现**：
- 仅支持密码哈希验证
- 三级权限：Root / Trustworthy / Untrustworthy
- 不支持过期时间、临时PWID等高级特性

### 2.4 HvFS 文件系统

**极简实现**：
- 仅支持目录和文件两种节点
- 简单权限检查（所有者/全局读）
- 不支持符号链接、ACL等

### 2.5 基础驱动

**极简实现**：
- 串口驱动（调试输出）
- PS/2 键盘驱动（用户输入）
- VGA 文本模式驱动（显示输出）
- 不支持网络、USB等

## 三、Linux 内核管辖范围参考

> 参考 Linux 宏内核设计理念，明确 AntX 内核的边界。

### 3.1 Linux 内核的核心管辖范畴

| 核心模块 | 管辖内容 | 核心目标 |
|----------|----------|----------|
| **进程/线程管理** | 进程创建/销毁/调度、线程同步（信号量/互斥锁）、PID管理、进程间通信（IPC） | 公平高效地分配CPU资源 |
| **内存管理** | 物理内存分页、虚拟地址映射、内存分配/释放（kmalloc/slab）、交换分区（Swap） | 安全隔离进程内存，最大化内存利用率 |
| **文件系统层（VFS）** | 抽象各类文件系统（ext4/FAT/NFS）、文件/目录操作、权限校验、缓存管理 | 统一文件操作接口，屏蔽底层存储差异 |
| **设备驱动框架** | 硬件驱动抽象层（PCI/USB/字符设备/块设备）、中断管理、I/O端口/内存管理 | 标准化硬件交互，适配不同硬件架构 |
| **网络协议栈** | TCP/IP/UDP等协议实现、套接字（Socket）抽象、网络设备驱动对接 | 统一网络数据收发接口 |
| **权限与安全** | UID/GID权限校验、Capabilities能力集、SELinux（可选） | 控制资源访问权限，保障系统安全 |
| **中断与异常处理** | 硬件中断响应、系统调用处理、页错误/除零等异常处理 | 衔接硬件与内核，处理突发情况 |

### 3.2 Linux 内核的「不管辖」范畴

- ❌ 不负责用户态交互（如Shell、终端界面、输入法）；
- ❌ 不负责应用逻辑（如浏览器、编辑器、数据库）；
- ❌ 不负责高级功能（图形界面、音视频解码、复杂输入法）；
- ❌ 不存储业务数据（仅管理存储介质，数据由用户态程序管理）。

### 3.3 AntX 内核只做「3件事」原则

#### 原则1：只管「硬件抽象」，不管「硬件使用」
- 内核仅提供「标准化硬件访问接口」（如键盘的`dev_read`、磁盘的`fs_read`），但不处理「如何使用硬件」（如键盘输入解析、磁盘文件格式解析）；
- 示例：AntX 键盘驱动仅返回原始扫描码，字符解析/输入法交给用户态；磁盘驱动仅管理块设备，文件系统逻辑（HvFS）仅保留核心块映射，目录解析交给用户态。

#### 原则2：只管「资源分配」，不管「资源使用」
- 内核仅负责「CPU/内存/存储」的分配与隔离（如给进程分配内存页、调度CPU时间片），但不关心进程「用这些资源做什么」（如计算、存储数据）；
- 示例：AntX 进程管理仅负责创建进程、分配栈空间、调度执行，进程要运行的程序逻辑完全由用户态提供。

#### 原则3：只管「权限校验」，不管「权限使用」
- 内核仅校验「谁能访问什么资源」（如PWID是否能读某个文件），但不干预「访问后做什么」（如读取后显示/修改/删除）；
- 示例：AntX 的`auth_verify`仅验证PWID密码，登录后的会话管理、命令执行交给用户态Shell。

## 四、AntX 内核模块极简设计

### 4.1 内核模块保留与剥离

| AntX 内核模块 | 保留内容（核心） | 剥离内容（用户态实现） |
|---------------|------------------|------------------------|
| **进程管理** | 进程创建（`proc_create`）、调度（基于优先级的简单调度器）、退出（`proc_exit`）、PID管理 | 进程间通信（管道/消息队列）、信号处理、进程组管理（用户态封装） |
| **内存管理** | 物理内存分页、虚拟地址映射、简单分配（`mem_brk`）、内存保护 | 内存映射（`mem_map`）、交换分区、内存缓存（用户态按需实现） |
| **文件系统（HvFS）** | 块设备映射、Inode核心结构、权限绑定（PWID）、基础读写（`fs_read`/`fs_write`） | 目录解析、文件缓存、日志、复杂权限（如ACL） |
| **设备驱动** | 中断管理、PS/2键盘/VGA/磁盘的基础驱动、`dev_read`/`dev_write`接口 | USB驱动、显卡驱动、声卡驱动（模块化加载，默认不内置） |
| **权限管理（PWID）** | 密码哈希校验、权限位检查（读/写/执行）、Root权限判断 | PWID创建/删除、备注修改、临时提权（用户态通过`auth_*`调用内核接口） |
| **系统调用** | 核心调用分发、参数合法性校验、错误码返回 | 系统调用封装（用户态库实现，如`ant_syscall`函数） |

### 4.2 极简进程调度器示例

```c
// AntX 极简进程调度器（核心代码）
#define MAX_PRIO 10 // 优先级0（最高）-9（最低）
static proc_t *runqueue[MAX_PRIO]; // 优先级队列
static proc_t *current_proc;       // 当前运行进程

// 调度核心：选最高优先级的进程执行
void sched_switch(void) {
    // 从高到低遍历优先级队列
    for (int i = 0; i < MAX_PRIO; i++) {
        if (runqueue[i]) {
            proc_t *next = runqueue[i];
            runqueue[i] = next->next;
            if (current_proc) {
                context_save(&current_proc->context);
                sched_add(current_proc);
            }
            current_proc = next;
            context_load(&current_proc->context);
            return;
        }
    }
    current_proc = &idle_proc;
    context_load(&current_proc->context);
}
```

### 4.3 内存池化设计

```c
// 极简内存池（进程PCB）
#define PCB_POOL_SIZE 64
static proc_t pcb_pool[PCB_POOL_SIZE];
static bool pcb_used[PCB_POOL_SIZE];

proc_t *pcb_alloc(void) {
    for (int i = 0; i < PCB_POOL_SIZE; i++) {
        if (!pcb_used[i]) {
            pcb_used[i] = true;
            memset(&pcb_pool[i], 0, sizeof(proc_t));
            return &pcb_pool[i];
        }
    }
    return NULL;
}
```

## 四、启动流程

> **重要改进** (2026-04-11): 采用双映射启动方案，详见 [内存管理文档](memory-management.md#24-内核启动双映射机制)

### 4.1 启动阶段

```
┌─────────────────────────────────────────────────────────────┐
│                     BIOS → GRUB                              │
│  加载内核到内存，跳转到入口                                   │
└─────────────────────────────┬───────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│              _start (32位保护模式, 物理地址)                  │

└─────────────────────────────┬───────────────────────────────┘
```

### 4.2 双映射启动技术要点

| 技术 | 实现方式 | 目的 |
|------|---------|------|
| 恒等映射 | 虚拟地址 = 物理地址 | 开启分页后不崩溃 |
| 高地址映射 | 虚拟地址 = 0xFFFF800001000000 + 物理地址 | 内核运行在高地址 |
| 2MB 大页 | PD 的 PS 位置位 | 减少页表层级 |
| RIP 相对跳转 | `lea rax, [rel label]` | 位置无关代码 |
| 代码复制 | `rep movsq` | 将内核代码从 LMA 复制到 VMA |
| TLB 刷新 | 重新加载 CR3 | 确保映射正确 |

### 4.4 用户态切换 (2026-04-13 调试)

用户态进程启动涉及从内核态 (CPL=0) 通过 `iretq` 切换到用户态 (CPL=3)。

**关键步骤**:
1. 构建 iretq 栈帧: SS → RSP → RFLAGS → CS → RIP
2. 设置 CR3 指向用户页表
3. 设置 DS/ES 段寄存器为用户数据段 (0x23)
4. 执行 `iretq` 切换到用户态

**已验证正确的部分**:

| 项目 | 状态 | 验证值 |
|------|------|--------|
| 用户代码页表映射 | ✅ | PTE: `P=1, RW=0, US=1, XD=0` |
| 用户栈映射 | ✅ | 物理地址可访问 |
| 内核栈映射到用户页表 | ✅ | 已映射 |
| CR3 切换 | ✅ | 指向用户页表 |
| 段选择子 | ✅ | CS=0x1B, SS=0x23 |
| RSP 对齐 | ✅ | 16字节对齐 |
| RFLAGS | ✅ | 0x202 (IF=1) |

## 六、设计原则总结

1. **极简优先**：只保留最小必要功能，尽快可运行
2. **可用为目标**：优先保证可交互、可调试
3. **PWID 核心**：权限设计围绕 PWID 模型
4. **边界清晰**：内核只管「硬件抽象、资源分配、权限校验」
5. **高效实现**：用最少的代码实现核心能力
6. **快速迭代**：先实现再优化，不追求一步到位

## 七、未来重构方向：裁判/运动员分离

> 参考 Linux 设计理念，AntX 内核将逐步重构为「裁判」角色，用户态承担「运动员」职责。

### 核心理念

| 角色 | 定位 | 职责 |
|------|------|------|
| 内核（裁判）| 资源管理者 | 权限校验、内存管理、进程调度、系统调用 |
| 用户态（运动员）| 业务实现 | PWID创建、文件初始化、系统配置、登录认证 |

### 内核职责（做减法）

- 仅保留核心「裁判」能力
- PWID 权限校验接口
- 文件系统块管理
- 进程创建/调度接口
- 不存储任何配置

### 用户态职责（做加法）

- init 进程（用户态 1 号）
- PWID 创建与管理
- HvFS 目录初始化
- 登录认证
- AntXShell 命令执行
