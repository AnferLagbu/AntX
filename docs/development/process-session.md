# AntX 进程与会话模型设计

> **实现状态说明**：本文档描述的进程与会话模型设计，部分已实现，部分仍在开发中。当前实现了基本的进程创建、调度和会话管理，进程树结构和高级调度特性尚未完全实现。

## 一、设计概述

### 1.1 核心思想

AntX 的进程管理采用**会话级 PWID**模型，与多会话身份机制完美契合：

- **会话（Session）**是进程管理的最小单位
- **PWID 绑定到会话**，而非单个进程
- 同一会话内的所有进程共享该 PWID 权限
- 进程创建时继承父进程的会话 PWID

### 1.2 当前实现状态

| 功能 | 状态 | 说明 |
|------|------|------|
| 进程创建 | ✅ 已实现 | process_create() |
| 进程调度 | ✅ 已实现 | 简单轮转调度 |
| 进程退出 | ✅ 已实现 | process_exit() |
| 会话管理 | ✅ 已实现 | 基本会话结构 |
| 进程树 | ⏳ 部分实现 | 父子关系已建立 |
| 多级反馈队列 | ⏳ 未实现 | 计划中 |
| PWID 感知调度 | ⏳ 未实现 | 计划中 |

### 1.2 与传统模型的对比

| 特性 | 传统 UNIX | AntX |
|------|-----------|------|
| 进程权限 | 继承父进程 UID | 继承会话 PWID |
| 权限变更 | 需要 setuid | 切换会话 PWID |
| 会话概念 | 存在但权限独立 | PWID 绑定到会话 |
| 临时提权 | sudo | 临时子进程 |

## 二、会话设计

### 2.1 会话结构

```
┌─────────────────────────────────────────────────────────────┐
│                        会话 (Session)                        │
├─────────────────────────────────────────────────────────────┤
│  session_id    : 会话唯一标识                                │
│  pwid          : 绑定到会话的 PWID                          │
│  terminal      : 关联的终端设备                             │
│  parent_sid    : 父会话 ID（用于会话树）                    │
│  create_time   : 创建时间                                   │
│  status        : 会话状态                                   │
│  process_list  : 会话进程链表                               │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 会话状态

| 状态 | 说明 |
|------|------|
| ACTIVE | 活跃，正在运行 |
| IDLE | 空闲，等待输入 |
| LOGGING_IN | 正在登录验证 |
| LOGGING_OUT | 正在注销 |
| ZOMBIE | 僵尸状态（等待资源回收） |

## 三、进程设计

### 3.1 进程结构（当前实现）

```c

struct process {
    uint64_t pid;
    uint64_t session_id;
    uint64_t parent_pid;
    uint64_t pwid;
    
    enum process_state state;
    uint64_t exit_code;
    
    int priority;
    uint64_t cpu_time;
    uint64_t start_time;
    uint64_t time_slice;
    
    uint64_t cr3;              // 页表基址
    uint64_t kernel_stack;
    uint64_t user_stack;
    
    struct cpu_context context;
    
    struct process *next;
    struct process *prev;
    struct process *parent;
    struct process *children;
    struct process *sibling;
};
```

**当前实现特点**：
- 简化的进程控制块
- 包含基本的调度信息
- 支持进程树结构（父子关系）
- 独立的页表和栈空间

## 四、进程操作

### 4.1 fork() - 进程创建

```
fork() 流程：
1. 复制当前进程结构
2. 复制页表（写时复制）
3. 继承父进程的 session_id 和 pwid
4. 设置为 READY 状态
5. 返回子进程 PID
```

**继承关系**：
```
父进程
  ├── session_id → 子进程继承
  ├── pwid       → 子进程继承
  ├── fd_table   → 子进程复制（引用计数+1）
  └── 内存       → 写时复制 (Copy-on-Write)
```

### 4.2 exec() - 程序执行

```
exec() 流程：
1. 加载新程序到当前进程空间
2. 重置堆栈
3. 保持 session_id 和 pwid 不变
4. 开始执行新程序
```

**特殊情况 - 提权 exec**：
```
exec() with 提权标志：
1. 创建临时子进程
2. 设置子进程 pwid = 原Root
3. 执行目标程序
4. 执行完毕，子进程销毁
5. 父进程保持原 pwid
```

### 4.3 exit() - 进程退出

```
exit() 流程：
1. 关闭所有文件描述符
2. 释放内存（标记为可回收）
3. 设置进程状态为 ZOMBIE
4. 通知父进程收集退出状态
5. 如果父进程已退出，init 收养
```

### 4.4 wait() - 等待子进程

```
wait() 流程：
1. 检查是否有僵尸子进程
2. 如果有，回收并返回状态
3. 如果没有，挂起等待
```

### 6.1 调度策略

**未来考虑**：

```c
struct scheduler {
    struct ready_queue {
        struct process *head;
        struct process *tail;
        int count;
    } queues[3];  // 3个优先级队列
    
    struct process *current;    // 当前运行进程
    uint64_t time_slice;        // 时间片大小

```

```
        │
        ▼

        ▼

        │
        ▼

        │
        ▼

        │
        ▼

```

## 七、安全考量

### 7.1 进程隔离

- 不同会话的进程内存完全隔离
- 页表独立，无法访问其他会话内存
- 文件描述符需要显式共享

### 7.2 PWID 检查点

| 操作 | PWID 检查 |
|------|-----------|
| fork | 继承会话 PWID |
| exec | 保持会话 PWID |
| 内存访问 | 检查页表 PWID 权限 |
| 文件访问 | 检查文件 ACL PWID |
| 系统调用 | 验证调用者 PWID |

### 7.3 提权限制

- 提权进程无法 fork 子进程（防止权限逃逸）
- 提权进程无法修改自身 PWID
- 提权进程执行完毕后必须退出
