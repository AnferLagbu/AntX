# AntX 内存管理设计

> **实现状态说明**：本文档描述的内存管理设计，当前实现为简化版本。物理内存管理使用位图分配器，虚拟内存管理使用简单的页表映射。Buddy System 和 Slab Allocator 等高级特性尚未实现。

## 一、设计概述

### 1.1 设计目标

- 简单可靠的分页内存管理
- 支持进程隔离
- 与 PWID 权限模型集成
- 支持写时复制 (Copy-on-Write) - **未实现**

### 1.2 当前实现状态

| 功能 | 状态 | 说明 |
|------|------|------|
| 物理内存管理 (PMM) | ✅ 已实现 | 使用位图分配器 (Rust重写) |
| 虚拟内存管理 (VMM) | ✅ 已实现 | 四级页表映射 (Rust重写) |
| 内核堆 (kmalloc) | ✅ 已实现 | Rust实现 |
| 进程隔离 | ✅ 已实现 | 每个进程独立页表 |

| Slab Allocator | ✅ 已实现 | C实现 `src/kernel/slab.c` |
| Buddy System | ⏳ 未实现 | 当前位图可满足需求 |

### 2.4 内核启动双映射机制

> **重要改进** (2026-04-11): 采用 Linux/Windows/BSD 标准的双映射启动方案

#### 2.4.1 设计原理

内核启动时需要解决「高地址代码在分页开启前无法访问」的问题。AntX 采用行业标准方案：

**双映射 (Double Mapping)**：
- **恒等映射 (Identity Mapping)**：虚拟地址 = 物理地址
- **高地址映射 (Higher Half Mapping)**：虚拟地址 = 0xFFFF800001000000 + 物理地址

#### 2.4.2 内存布局

```
启动阶段内存布局：
┌────────────────────────────────────────────────────────────────┐
│ 物理地址        │ 虚拟地址              │ 内容                  │
├────────────────────────────────────────────────────────────────┤
│ 0x100000       │ 0x100000 (恒等映射)    │ multiboot2 header    │
│ 0x101000       │ 0x101000              │ .boot.text (启动代码) │
│ 0x102000       │ 0x102000              │ .bootbss (页表、栈)   │
│                │                       │ - pml4 (4KB)         │
│                │                       │ - pdpt_low (4KB)     │
│                │                       │ - pdpt_high (4KB)    │
│                │                       │ - pd_low (4KB)       │
│                │                       │ - pd_high (4KB)      │
│                │                       │ - gdt64 (30B)        │
│                │                       │ - stack (64KB)       │
├────────────────────────────────────────────────────────────────┤
│ 0x118000 (LMA) │ 0xFFFF800001118000    │ .text (内核代码)      │
│ ...            │ ...                   │ .rodata, .data, .bss │
└────────────────────────────────────────────────────────────────┘

注：LMA = Load Memory Address (加载地址)
     VMA = Virtual Memory Address (虚拟地址)
```

#### 2.4.3 页表结构

```
双映射页表结构：

PML4 (Page Map Level 4):
┌─────────────────────────────────────────────────────────────┐
│ Entry 0     → pdpt_low  (恒等映射)                          │
│ Entry 256   → pdpt_high (高地址映射 0xFFFF8000...)          │
│ Entry 511   → (未使用)                                      │
└─────────────────────────────────────────────────────────────┘

PDPT (Page Directory Pointer Table):
┌─────────────────────────────────────────────────────────────┐
│ pdpt_low[0]  → pd_low   (恒等映射)                          │
│ pdpt_high[0] → pd_high  (高地址映射)                        │
└─────────────────────────────────────────────────────────────┘

PD (Page Directory) - 使用 2MB 大页:
┌─────────────────────────────────────────────────────────────┐
│ pd_low[0-511]  : 0x0      → 0x0      (1TB 恒等映射)         │
│ pd_high[0-511] : 0xFFFF800001000000 → 0x0 (1TB 高地址映射)  │
└─────────────────────────────────────────────────────────────┘

每个 PD entry 映射 2MB，512 个 entry = 1GB
每个 PDPT entry 指向一个 PD，可映射 512GB
完整映射 1TB 物理内存
```

#### 2.4.4 启动流程

```
启动流程：
┌─────────────────────────────────────────────────────────────┐
│ 1. GRUB 加载内核                                             │
│    - boot 部分 → 物理地址 0x100000 (恒等映射区域)            │
│    - kernel 部分 → 物理地址 0x118000 (LMA)                   │
└─────────────────────────────┬───────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│ 2. _start (32位保护模式, 物理地址 0x101000)                  │
│    - 创建双映射页表 (pd_low + pd_high)                       │
│    - 设置 GDT                                                │
│    - 加载 CR3 (页表基址)                                     │
│    - 开启 PAE (CR4.PAE)                                      │
│    - 开启长模式 (IA32_EFER.LME)                              │
│    - 开启分页 (CR0.PG)                                       │
└─────────────────────────────┬───────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│ 3. trampoline64 (64位长模式, 仍在物理地址)                   │
│    - 加载 64位段选择子                                       │
│    - RIP 相对跳转到高地址                                    │
└─────────────────────────────┬───────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│ 4. trampoline64_high (高地址虚拟地址)                        │
│    - 复制内核代码: LMA (0x118000) → VMA (0xFFFF800001118000) │
│    - 刷新 TLB (重新加载 CR3)                                 │
│    - 设置高地址栈                                            │
│    - 调用 kernel_main                                        │
└─────────────────────────────────────────────────────────────┘
```

#### 2.4.5 关键代码实现

**链接脚本 (link.ld)**:
```ld
SECTIONS
{
    . = 0x100000;                    /* boot 部分物理地址 */
    
    .multiboot2 : { *(.multiboot2) }
    .boot.text : { build/boot.o(.text) }
    .bootbss : { *(.bootbss) }       /* 页表、栈 */
    
    _boot_end = .;
    _kernel_text_lma = .;            /* 内核代码 LMA */
    _kernel_text_vma = 0xFFFF800001000000 + .;  /* 内核代码 VMA */
    
    . = _kernel_text_vma;
    
    .text : AT(_kernel_text_lma) {   /* 高地址 VMA, 低地址 LMA */
        *(.text)
    }
    /* ... */
}
```

**启动代码 (boot.asm)**:
```asm
; 创建双映射
lea edi, [ebx + (pd_low - _start)]
mov eax, 0x87              ; Present + Writable + 2MB Page
mov ecx, 512
.map_low:
    mov [edi], eax
    add eax, 0x200000
    loop .map_low

lea edi, [ebx + (pd_high - _start)]
mov eax, 0x87
mov ecx, 512
.map_high:
    mov [edi], eax
    add eax, 0x200000
    loop .map_high

; 进入高地址后复制内核代码
trampoline64_high:
    mov rsi, qword 0x118000         ; 源: 物理地址
    mov rdi, qword 0xFFFF800001118000 ; 目标: 高地址
    mov rcx, qword 0x124000
    shr rcx, 3
    rep movsq                       ; 复制

    mov rax, 0xFFFF800001118000    ; TLB 刷新
    invlpg [rax]                    ; 使用寄存器间接寻址

    mov rax, cr3
    mov cr3, rax                    ; 刷新 TLB

    mov rsp, qword 0xFFFF8000011701e ; 设置栈

    mov rax, qword 0xFFFF8000011182bb ; kernel_main
    call rax
```

#### 2.4.6 技术优势

| 特性 | 说明 |
|------|------|
| **行业标准** | Linux/Windows/BSD 统一采用此方案 |
| **内存安全** | boot 代码不会被复制操作覆盖 |
| **扩展性强** | 支持未来 SMP 多核启动 |
| **TLB 一致** | 复制后刷新 TLB 确保映射正确 |
| **大页优化** | 使用 2MB 大页减少页表层级 |

```c
// 当前实现 (src/mm/pmm.c)
#define BITMAP_SIZE 32768
static uint32_t bitmap[BITMAP_SIZE];

void* pmm_alloc_page(void) {
    for (uint64_t i = 0; i < BITMAP_SIZE * 32; i++) {
        if (test_bit(i)) {
            clear_bit(i);
            mem_info.free_pages--;
            return (void*)(i * PAGE_SIZE);
        }
    }
    return NULL;
}
```

**特点**：

### 4.3 虚拟内存管理（当前实现）

**实现方式**：简单的四级页表映射

```c
// 当前实现 (src/mm/vmm.c)
void vmm_map_page(uint64_t virt, uint64_t phys, uint64_t flags) {
    pte_t* pml4 = (pte_t*)kernel_pml4;
    
    pte_t* pdpt = get_page_table((uint64_t)pml4, PML4_INDEX(virt), 1);
    pte_t* pd = get_page_table((uint64_t)pdpt, PDPT_INDEX(virt), 1);
    pte_t* pt = get_page_table((uint64_t)pd, PD_INDEX(virt), 1);
    
    pte_t* entry = &pt[PT_INDEX(virt)];
    entry->fields.present = (flags & PAGE_PRESENT) ? 1 : 0;
    entry->fields.rw = (flags & PAGE_WRITABLE) ? 1 : 0;
    entry->fields.user = (flags & PAGE_USER) ? 1 : 0;
    entry->fields.frame = phys >> 12;
}
```

**特点**：
- 使用启动时创建的页表
- 支持用户进程独立页表
- 内核空间共享映射

```
│  会话 1 (PWID=0xA1B2)         会话 2 (PWID=0xC3D4)         │
│  ┌─────────────────┐          ┌─────────────────┐          │
│  │ 进程 A 的页表    │          │ 进程 B 的页表   │          │
│  │ 0x0000 - 0x1000 │          │ 0x0000 - 0x1000 │          │
│  │ → 物理页 #1     │          │ → 物理页 #5     │          │
│  └─────────────────┘          └─────────────────┘          │
│                                                               │
│  物理内存:                                                   │
│  ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐   │
│  │ 页 #1  │ │ 页 #2  │ │ 页 #3  │ │ 页 #4  │ │ 页 #5  │   │
│  │ (A)   │ │ (A)   │ │ (A)   │ │ (A)   │ │ (B)   │   │
│  └────────┘ └────────┘ └────────┘ └────────┘ └────────┘   │
│                                                               │
│  页表隔离：进程 A 无法访问物理页 #5（属于进程 B）           │
│                                                               │
└─────────────────────────────────────────────────────────────┘
```

### 6.2 权限检查

```c
// 内存访问权限检查
bool check_memory_access(uint64_t addr, int access_type, uint64_t pwid) {
    struct vm_area_struct *vma = find_vma(current->mm, addr);
    
    if (!vma) return false;
    
    // 检查 PWID 是否匹配
    if (vma->pwid != 0 && vma->pwid != pwid) {
        return false;
    }
    
    // 检查访问类型
    if (access_type == WRITE && !(vma->vm_flags & VM_WRITE)) {
        return false;
    }
    
    return true;
}
```

## 七、换页与回收

### 7.1 页面回收策略

- **主动回收**：内存不足时触发
- **LRU 列表**：最近最少使用优先
- **交换空间**：支持将页面换出到磁盘（可选）

### 7.2 页面类型

| 类型 | 说明 | 可回收 |
|------|------|--------|
| 匿名页 | 堆、栈 | 是 |
| 文件映射 | mmap 文件 | 是（脏页写回） |
| 共享内存 | IPC | 是 |
| 内核数据 | 内核态 | 否 |
| 进程代码 | TEXT 段 | 否 |

## 八、内存错误处理

### 8.1 缺页异常

```
缺页异常处理流程：

1. 保存错误上下文
2. 分析错误地址
       │
       ├── VM_FAULT_PRESENT → 页面存在，但权限不足
       │       └── 检查权限，返回 -EACCES
       │
       ├── VM_FAULT_WRITE → 写时复制
       │       └── 分配新页，复制内容
       │
       ├── VM_FAULT_MAJOR → 页面不在内存
       │       └── 从磁盘换入
       │
       └── VM_FAULT_NOPAGE → 页面不存在
               └── 返回 -SEGV
```

### 8.2 内存不足处理

```
内存不足时：
1. 触发 OOM Killer
2. 选择进程（基于 oom_score）
3. 杀死选中的进程
4. 回收其内存资源
```
