# AntX 内存管理设计

## 一、设计概述

### 1.1 设计目标

- 简单可靠的分页内存管理
- 支持进程隔离
- 与 PWID 权限模型集成
- 支持写时复制 (Copy-on-Write)

### 1.2 内存管理架构

```
┌─────────────────────────────────────────────────────────────┐
│                      内存管理架构                             │
├─────────────────────────────────────────────────────────────┤
│                                                               │
│   ┌─────────────────────────────────────────────────────┐   │
│   │                  页分配器                            │   │
```

### 3.2 页表项结构

```c
// PML4/PDPT/PD/PT 通用格式
struct page_table_entry {
    uint64_t present    : 1;   // 页存在
    uint64_t rw         : 1;   // 读/写
    uint64_t user      : 1;   // 用户/内核
    uint64_t pwt       : 1;   // 写穿透
    uint64_t pcd       : 1;   // 禁用缓存
    uint64_t accessed  : 1;   // 已访问
    uint64_t dirty     : 1;   // 已修改
    uint64_t pat       : 1;   // PAT
    uint64_t global    : 1;   // 全局页
    uint64_t available : 3;   // 可用
    uint64_t addr      : 40;  // 物理地址
    uint64_t available2: 11;  // 可用
    uint64_t xd        : 1;   // 执行禁用
};
```

### 3.3 PWID 权限扩展

为支持 PWID 权限控制，扩展页表项：

```c
struct pwid_page_table_entry {
    struct page_table_entry base;
    uint64_t pwid_mask;      // PWID 访问掩码
    uint64_t pwid_owner;     // 所有者 PWID
    uint8_t  pwid_enforce;   // PWID 强制执行标志
};
```

### 5.2 写时复制 (Copy-on-Write)

```
fork() 时的 COW 机制：

父进程                    子进程
  │                         │
  ▼                         │
┌──────────┐              ┌──────────┐
│ 代码段   │◄──共享──►│ 代码段   │
│ (只读)   │              │ (只读)   │
├──────────┤              ├──────────┤
│ 读/写页  │◄──共享──►│ 读/写页  │
│ (共享)   │  (都标记为│ (共享)   │
│          │   只读)   │          │
└──────────┘              └──────────┘

写操作触发缺页异常：
  │
  ▼
┌──────────────────┐
│ 分配新物理页    │
│ 复制内容        │
│ 设置为可写      │
└──────────────────┘
  │
  ▼
每个进程拥有独立副本
```

## 六、内存隔离

### 6.1 基于会话的内存隔离

不同会话（PWID）的进程内存完全隔离：

```
┌─────────────────────────────────────────────────────────────┐
│                     进程内存隔离                              │
├─────────────────────────────────────────────────────────────┤
│                                                               │
│  会话 1 (PWID=0xA1B2)         会话 2 (PWID=0xC3D4)         │
│  ┌─────────────────┐          ┌─────────────────┐          │
│  │ 进程 A 的页表    │          │ 进程 B 的页表   │          │
│  │ 0x0000 - 0x1000 │          │ 0x0000 - 0x1000 │          │
│  │ → 物理页 #1     │          │ → 物理页 #5     │          │
│  └─────────────────┘          └─────────────────┘          │
│                                                               │
│  物理内存:                                                   │
│  ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐   │
│  │ 页 #1  │ │ 页 #2  │ │ 页 #3  │ │ 页 #4  │ │ 页 #5  │   │
│  │ (A)   │ │ (A)   │ │ (A)   │ │ (A)   │ │ (B)   │   │
│  └────────┘ └────────┘ └────────┘ └────────┘ └────────┘   │
│                                                               │
│  页表隔离：进程 A 无法访问物理页 #5（属于进程 B）           │
│                                                               │
└─────────────────────────────────────────────────────────────┘
```

### 6.2 权限检查

```c
// 内存访问权限检查
bool check_memory_access(uint64_t addr, int access_type, uint64_t pwid) {
    struct vm_area_struct *vma = find_vma(current->mm, addr);
    
    if (!vma) return false;
    
    // 检查 PWID 是否匹配
    if (vma->pwid != 0 && vma->pwid != pwid) {
        return false;
    }
    
    // 检查访问类型
    if (access_type == WRITE && !(vma->vm_flags & VM_WRITE)) {
        return false;
    }
    
    return true;
}
```

## 七、换页与回收

### 7.1 页面回收策略

- **主动回收**：内存不足时触发
- **LRU 列表**：最近最少使用优先
- **交换空间**：支持将页面换出到磁盘（可选）

### 7.2 页面类型

| 类型 | 说明 | 可回收 |
|------|------|--------|
| 匿名页 | 堆、栈 | 是 |
| 文件映射 | mmap 文件 | 是（脏页写回） |
| 共享内存 | IPC | 是 |
| 内核数据 | 内核态 | 否 |
| 进程代码 | TEXT 段 | 否 |

## 八、内存错误处理

### 8.1 缺页异常

```
缺页异常处理流程：

1. 保存错误上下文
2. 分析错误地址
       │
       ├── VM_FAULT_PRESENT → 页面存在，但权限不足
       │       └── 检查权限，返回 -EACCES
       │
       ├── VM_FAULT_WRITE → 写时复制
       │       └── 分配新页，复制内容
       │
       ├── VM_FAULT_MAJOR → 页面不在内存
       │       └── 从磁盘换入
       │
       └── VM_FAULT_NOPAGE → 页面不存在
               └── 返回 -SEGV
```

### 8.2 内存不足处理

```
内存不足时：
1. 触发 OOM Killer
2. 选择进程（基于 oom_score）
3. 杀死选中的进程
4. 回收其内存资源
```

## 九、简单实现优先

### 9.1 现阶段的简化设计

- 固定 4KB 页大小
- 简单物理内存分配器（位图）
- 不实现交换空间
- 简化页面回收

### 9.2 未来可扩展

- 支持大页 (Huge Pages)
- 支持内存压缩
- 支持持久内存
- 支持 NUMA 感知
