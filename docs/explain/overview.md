# AntX 系统概述

> **AntX** (Ant eXtended) - 一个具有创新故障恢复机制的现代化宏内核操作系统

---

## 🎯 设计目标

AntX旨在构建一个具有以下特性的操作系统内核：

1. **高可靠性** - 通过栏栈机制实现模块级故障恢复
2. **高安全性** - 基于能力的细粒度权限控制
3. **高性能** - 优化的内核数据结构和算法
4. **可扩展性** - 模块化设计，易于扩展新功能
5. **可移植性** - 支持多架构（当前x86_64，未来ARM64/RISC-V）

---

## 🌟 核心创新

### 1. 栏栈恢复机制 (Barrier Stack)

AntX最核心的创新是**栏栈恢复机制**，这是一种全新的内核故障恢复策略。

**传统方法的问题**:
- Linux kexec: 重启整个内核，丢失所有状态
- 微内核: 模块隔离但性能开销大
- 宏内核: 单点故障导致整个系统崩溃

**栏栈的解决方案**:
```
BBR (Barrier Base Recovery)  → 基础层：单模块回滚
BSR (Barrier Soft Reset)     → 软重启：回滚到初始栏
BHR (Barrier Hard Reset)     → 硬重启：硬件级重置
```

**优势**:
- 恢复速度快（毫秒级 vs 秒级）
- 状态保留（只回滚故障模块）
- 并发支持（独立模块并行恢复）
- 成功率高（测试显示95%+恢复成功率）

详见 [栏栈恢复子系统](../explain/barrier/)

---

### 2. PWID安全模型

基于能力的权限控制系统，摒弃传统的Unix权限模型。

**核心概念**:
- **PWID** (Privileged Workload ID): 特权工作负载标识
- **Capability Matrix**: 16×64位能力矩阵
- **Trust Chain**: 信任链传递

**优势**:
- 细粒度权限控制
- 无Root概念，更安全
- 支持委托和撤销
- 审计追踪完整

详见 [安全子系统](../explain/security/)

---

### 3. HvFS混合文件系统

创新的混合文件系统，支持内存模式和磁盘模式无缝切换。

**特性**:
- 内存模式：高性能，适合测试
- 磁盘模式：持久化，适合生产
- 运行时切换：无需重启
- ZFS风格：写时复制、快照、校验和

详见 [HvFS文件系统](../changelog.md)

### 关键设计决策

1. **宏内核架构**
   - 所有核心服务在内核态运行
   - 通过栏栈实现模块隔离效果
   - 性能优于微内核

2. **混合语言实现**
   - Rust: 核心子系统（内存安全）
   - C: 硬件交互、遗留代码
   - 汇编: 启动、上下文切换

3. **事件驱动调度**
   - 基于优先级的抢占式调度
   - 支持实时任务
   - 公平调度保证

## 📦 核心子系统

### 1. 内存管理
- **PMM** (物理内存管理器): 位图分配
- **VMM** (虚拟内存管理器): 页表管理
- **堆管理器**: kmalloc/kfree
- **内存映射**: IO映射、DMA

### 2. 进程管理
- **进程控制块**: 完整的进程状态
- **调度器**: 优先级+时间片
- **上下文切换**: 高效的寄存器保存/恢复
- **进程间通信**: 共享内存、消息队列

### 3. 文件系统
- **VFS**: 统一文件系统接口
- **RamFS**: 内存文件系统
- **HvFS**: 混合文件系统
- **DevFS**: 设备文件系统
- **ProcFS**: 进程信息文件系统

### 4. 安全子系统
- **PWID**: 身份标识与验证
- **Capability**: 能力矩阵管理
- **Session**: 会话管理
- **Audit**: 审计日志

### 5. 栏栈恢复
- **BBR**: 基础恢复
- **BSR**: 软重启
- **BHR**: 硬重启
- **并发恢复**: SMP并行回滚

### 6. 驱动框架
- **统一驱动模型**: Driver trait
- **设备管理**: 设备注册与查找
- **中断处理**: IDT管理
- **DMA**: 直接内存访问

### 7. 网络栈
- **LWIP集成**: 轻量级TCP/IP栈
- **网络接口**: 以太网驱动
- **协议支持**: TCP/UDP/ICMP/ARP
- **应用层**: HTTP/Telnet

## 🔄 启动流程

```
BIOS/UEFI
    ↓
Bootloader (GRUB2)
    ↓
Multiboot2 Header
    ↓
boot.asm (实模式 → 保护模式)
    ↓
entry.asm (长模式设置)
    ↓
kernel_main() (C初始化)
    ↓
Rust初始化 (核心子系统)
    ↓
    ├─ PMM初始化
    ├─ VMM初始化
    ├─ 堆初始化
    ├─ IDT初始化
    ├─ 栏栈初始化
    ├─ VFS初始化
    ├─ PWID初始化
    ├─ 进程管理器初始化
    └─ 调度器初始化
    ↓
启动用户态init进程
    ↓
用户态Shell (axsh)
```

## 🧪 测试策略

AntX采用四级测试策略：

### 1. 单元测试
- 测试范围：单个函数/模块
- 数量：256个测试
- 覆盖率：90%+
- 执行时间：< 2分钟

### 2. 集成测试
- 测试范围：子系统间交互
- 数量：7个测试套件
- 覆盖：启动、内存、文件系统、进程、安全、栏栈
- 执行时间：< 1分钟

### 3. 压力测试
- 测试范围：高负载、边界条件
- 项目：内存压力、SMP稳定性、快速重启
- 执行时间：~3分钟

### 4. 混沌测试
- 测试范围：故障注入与恢复
- 故障率：5%
- 恢复成功率：95%+
- 执行时间：< 2分钟
